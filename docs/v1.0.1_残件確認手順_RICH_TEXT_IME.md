# Field Cross Search v1.0.1 残件確認手順（RICH_TEXT / IME）

作成日: 2026-09-18
対象: 確認用 ZIP `build/kintone-field-cross-search-plugin-v1.0.1-test.zip`（コードは freeze 中。本手順でコード・ZIP は変更しない）

## 現状

| 項目 | 状態 | 補足 |
|---|---|---|
| RICH_TEXT | FAIL（暫定） | Cross Search の query は `リッチエディター like "東京"`。kintone 標準の絞り込みでも同じ語で 0 件。JavaScript エラーなし |
| IME | 未確認 | ブラウザ自動操作では再現できないため、利用者の手動確認とする |

標準の絞り込みでも 0 件だったため、現時点の観測は下記判定の **A**（Cross Search 固有の不具合とは扱わない）に当たる。
`like` 検索は検索用インデックスの作成タイミングにより、登録・更新直後のデータが一時的にヒットしないことがあるため、時間を置いた再確認と、以前からあるレコードでの確認で **C** かどうかを切り分ける。

## 1. RICH_TEXT 再確認

### 1-0. 比較条件をそろえる（重要）

Cross Search と標準の絞り込みで結果を比べるため、次の条件を固定する。

- 一覧は「（すべて）」など **絞り込み条件のない一覧** を使う。別の絞り込みが残っていると件数が合わない。
- Cross Search は選択した全フィールドを OR で検索するため、他のフィールドでヒットすると比較にならない。
  確認の間だけ、プラグイン設定の検索対象を **リッチエディターのフィールド 1 つだけ** にする（確認後に元へ戻す）。
- AND / OR はどちらでもよい（1 語のため結果は同じ）。
- 検索語は「東京」（2 文字以上の日本語）。
- まず **装飾なしのプレーンな文字** で確認する。語の途中で太字・色などの装飾が切り替わる文字列（例:「東」だけ太字）は、別ケースとして後で確認する。

```

[ ] R-0-2 プラグイン設定の検索対象をリッチエディターのフィールドだけにして保存した       結果: (      )
[ ] R-0-3 一覧の検索バーに「対象：1件」と表示される                                  結果: (      )
```

### 1-1. 新規レコードで確認

新規レコードのリッチエディターに、装飾なしで次の文を入力して保存する。

```
東京支店の営業担当です。
```

保存時刻: ____ : ____　レコード番号: ________

次の 3 つのタイミングで、Cross Search と標準の絞り込みの両方を確認する。

| タイミング | Cross Search「東京」 | 標準の絞り込み「次のキーワードを含む: 東京」 | 両者は同じ結果か |
|---|---|---|---|
| T0 保存直後 | ヒット / 0件 | ヒット / 0件 | 同じ / 違う |
| T1 約10分後 | ヒット / 0件 | ヒット / 0件 | 同じ / 違う |
| T2 約1時間後（または翌日） | ヒット / 0件 | ヒット / 0件 | 同じ / 違う |

### 1-4. 判定

| 判定 | 条件 | 扱い |
|---|---|---|
| **A** | 標準の絞り込みでも 0 件、Cross Search でも 0 件（時間を置いても、既存レコードでも） | Cross Search 固有の不具合とは扱わない。RICH_TEXT 対応コードは維持。README の注意書きに「リッチエディターの検索結果は kintone 標準の絞り込みと同じ」旨を足すかを別途判断 |
| **B** | 標準の絞り込みではヒット、Cross Search では 0 件 | Cross Search 側の不具合として調査対象。下の「B の場合に控える情報」を記録して連絡 |

補足: 新規レコード（1-1）が T2 でも 0 件で、既存レコード（1-2）はヒットする場合は **C に準ずる**（反映に時間がかかっている）として、翌日にもう一度 1-1 を確認する。

## 2. IME（手動確認）

利用者自身が、日本語入力（Microsoft IME / Google 日本語入力 / macOS 日本語入力など）で確認する。
DevTools の Network タブを開いておくと、一覧の再読み込みが起きたかどうかが分かりやすい。

| 手順 | 操作 | 期待 |
|---|---|---|
| 1 | 検索欄で「とうきょう」と入力し、スペースキーで「東京」に変換する | 変換候補が表示される |
| 2 | Enter で変換を確定する | 「東京」が確定する |
| 3 | （この時点の画面を確認） | **検索されない**（一覧が再読み込みされない、URL が変わらない） |
| 4 | もう一度 Enter を押す | ― |
| 5 | （画面を確認） | **検索が 1 回だけ実行される**（再読み込みは 1 回、「検索中: 東京 / …」が表示される） |

```
[ ] I-1 手順 2 の確定 Enter では検索されなかった                                      結果: (      )
[ ] I-2 手順 4 の Enter で検索が 1 回だけ実行された                                   結果: (      )
[ ] I-3 使用したブラウザと IME:  ブラウザ ________  /  IME ________
[ ] I-4 （可能なら）別のブラウザでも同じ結果だった                                     結果: (      )
```

FAIL の場合に控える情報:

```

OS・IME:

```
